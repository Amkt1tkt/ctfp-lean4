# 序言

> 写一本给程序员看的**范畴论**（category theory），这个念头我已经在心里放了一阵子。注意，是程序员，不是计算机科学家——是工程师，不是科学家。我知道这听上去很疯。我害怕，而且怕得有道理。科学和工程之间隔着一道巨大的鸿沟，这我没法否认，因为鸿沟两边我都工作过。可我心里一直有一股很强的冲动，非把事情讲明白不可。我特别佩服理查德·费曼（Richard Feynman），他是把解释做简单的大师。我知道自己比不了费曼，但我会尽力。我先把这篇序言发出来——按理说，它该说服你去学范畴论——希望能引出讨论，也听到一些反馈。
>
> 你也可以看我面对现场观众讲这些内容：[讲座从这里开始](https://www.youtube.com/watch?v=I8LbkfSSR58&list=PLbgaMIhjbmEnaH_LTkxLI7FMa2HsnawM_)（或者在 YouTube 上搜索 “bartosz milewski category theory”）。

下面短短几段，我想试着说服你：这本书是写给你的。你也许觉得，不该把所谓“充裕的业余时间”拿去学数学里最抽象的一支。这类反对意见，全都站不住脚。

我这么乐观，是因为看到了几件事。第一，范畴论是一座宝库，里面装的都是特别管用的编程想法。Haskell 程序员取用这些想法，已经很久了。它们也在慢慢渗进别的语言，只是渗得太慢。我们得把这个过程加快。

第二，数学有很多种，投合的人也不一样。你也许对微积分过敏，对代数也过敏，但这不等于你就不会享受范畴论。我甚至敢说，范畴论这种数学，特别配程序员的脑子。因为它不怎么跟一个个具体的东西打交道，它跟结构打交道，就是那种让程序可以**复合**（composition）起来的结构。

复合正是范畴论的根——它写在**范畴**（category）的定义里面。我还要很认真地说：复合就是编程的本质。我们复合各种东西，远在某位伟大的工程师想出“子程序”之前就开始了。早些时候，结构化编程的原则给编程带来了一场革命，因为它让一块一块的代码变得可以复合。然后来的是面向对象编程，它整件事就是在复合对象。函数式编程要做的，不只是复合函数和代数数据结构（algebraic data structure）——它还让并发（concurrency）变得可以复合——这件事，别的编程范式几乎做不到。

第三，我有一件秘密武器：一把屠夫的刀。我要用这把刀把数学屠开，屠到程序员愿意下口。你要是职业数学家，就得非常小心：每条假设都要理清，每句话都要加上恰如其分的限定，每个证明都要严格地写出来。这样一来，数学论文和数学书对外人就极难读。我是学物理出身的。物理学里，我们靠不那么正式的推理，做出过惊人的进展。数学家曾经嘲笑狄拉克 $\delta$ 函数（Dirac delta function）。那是伟大的物理学家 P. A. M. 狄拉克为了解几个微分方程，当场造出来的。直到他们发现，微积分里一门全新的分支——分布论（distribution theory，也常叫广义函数论）——把狄拉克的洞见形式化了，他们才不笑了。

当然，挥手式的论证（hand-waving）有个风险：你会说出明摆着的错话。所以我会尽量保证，这本书里那些非正式的论证背后，站着扎实的数学理论。我床头柜上确实躺着一本翻烂了的《Categories for the Working Mathematician》，桑德斯·麦克莱恩（Saunders Mac Lane）写的。书名的意思是：给正在工作的数学家看的范畴论。

既然这是写给程序员的范畴论，每一个重要概念我都会用代码来说明。你大概也清楚，函数式语言比更流行的命令式语言更贴近数学，抽象能力也更强。于是很容易就会有人劝你：你必须先学会 Haskell，范畴论的这笔财富才轮得到你。可这么说，就等于暗示范畴论出了函数式编程就没有应用，而这根本不是事实。所以例子不能只停在一种语言里。本书用 Lean 4 写主要的代码；要把同一件事放回命令式、所有权和系统编程里看时，再辅以 Rust。Lean 4 既是一门函数式编程语言，又是一个证明助手：范畴论里的定律可以写成定理，由机器来检查。诚然，到了 Rust 这一侧，你得对付借用和生命周期，模式有时会埋进一长串 trait 约束里，你偶尔仍得复制一段 `impl`，拿它顶替更高的抽象——可这就是写系统语言的人的命。要写清楚的那层抽象，交给 Lean。

不过，就这门更贴近数学的语言而言，你也别想脱身。你不必先成为 Haskell 程序员，但你需要这样一门语言：用它来勾勒想法、把想法写成文档，再拿到你真正交付的代码里去实现。我当年开始用 Haskell，就是这么回事。我发现，它精练的语法和强大的类型系统，对理解并实现 C++ 的模板、数据结构和算法，帮助极大。你手里的这个版本把这门语言换成了 Lean 4。它做 Haskell 当年做的事，并且多走一步：写下来的定律，机器可以检查。我不能假定你已经会 Lean，所以会慢慢讲，用到什么就解释什么。

如果你已经写了很久程序，也许会问自己：我都写了这么多年，既没操心过范畴论，也没操心过函数式方法，到底是什么变了？你一定已经注意到，新的函数式特性正源源不断地侵入命令式语言。连 Java 这座面向对象的堡垒，也把 lambda 放了进来。C++ 近来追赶这个变化中的世界，速度快得发疯——每隔几年就一个新标准。所有这些动静，都是在为一场颠覆性的变化做准备，也就是我们搞物理的所说的相变（phase transition）。水要是一直加热，终究会烧开。我们现在就像那只青蛙，必须决定：是继续在越来越烫的水里游，还是开始另找出路。

![手绘：一只热得冒汗的青蛙，旁边立着温度计](/img/0.0/img_1299.jpg)

推动这场大变化的力量不止一股，其中一股是多核革命。眼下占上风的编程范式是面向对象。它在并发和并行这件事上什么也替你买不来，反倒鼓励又危险、又爱出 bug 的设计。数据隐藏是面向对象的基本前提。它一旦叠上共享和就地修改，就成了数据竞争（data race）的配方。把互斥锁（mutex）和它保护的数据捆在一起，这个主意挺好。可惜，锁不能复合。把锁藏起来，只会让死锁（deadlock）更容易发生，也更难查。

就算没有并发，软件系统越来越复杂，也在试探命令式范式还能把规模做到什么地步。说白了，**副作用**（side effect）已经开始失控。诚然，带副作用的函数往往很方便，也很好写。效果原则上可以编进名字里，也可以写进注释里。一个叫 `SetPassword` 或者 `WriteFile` 的函数，显然在修改某份状态，也显然在制造副作用，这种事我们都习惯应付。只有当你开始把带副作用的函数，复合到别的带副作用的函数上面，然后再往上复合，一层叠一层，事情才开始缠成一团。不是副作用天生就坏——坏在它们躲在看不见的地方，规模一大就没法管。副作用上不了规模，而命令式编程从头到尾就是副作用。

硬件在变，软件也越来越复杂，这两件事逼着我们重新想编程的地基。我们就像欧洲那些宏伟的哥特式大教堂的建造者，把手艺打磨到材料和结构所能允许的极限。法国博韦有一座[没有完工的哥特式主教座堂](https://en.wikipedia.org/wiki/Beauvais_Cathedral)，它站在那里，为这场人和自身极限之间深深的较量做证。人们本想让它在高度和轻盈上打破以往一切纪录，它却一次又一次地垮塌。铁杆和木支架这类临时措施，让它不至于散架；可显然，已经有好多事情不对了。用今天的眼光看，那么多哥特式建筑竟然建成了，没有现代材料科学，没有计算机建模，没有有限元分析，也没有一般意义上的数学和物理来帮忙。这简直是个奇迹。我希望后人看我们建造复杂操作系统、Web 服务器和互联网基础设施时显出来的编程本事，也能同样佩服。说真的，他们理应佩服，因为我们做成这一切，靠的理论基础单薄得可怜。要想继续往前走，就得把这些地基修好。

## 关于这个版本

*本节是译者补充，不是 Milewski 原序的一部分。*

上面的正文是原序的译文。原序说，例子会用 Haskell 来勾勒想法，再用大量 C++ 落到工程里。你手里的这一版改了这条路：主要例子用 Lean 4，需要对照命令式和系统编程时辅以 Rust。Lean 4 既是函数式编程语言，又是证明助手，范畴论里的定律可以写成定理，由机器检查。Milewski 自己的经历——他靠 Haskell 去理解 C++ 模板——仍按他的口气保留在上文里。

这本书是写给 Rust 程序员的。你正在学 Lean 4，或者打算学。数学基础薄弱也没关系：大致是高中数学，再加上一点离散数学的感觉，就够起步。读的过程里，用到什么就补什么。目标是读完之后，范畴论你真的懂了，Lean 4 的证明你也能读写。

建议的顺序是：先读 [Lean 4 速成](/guide/lean-for-rustaceans)，再读 [数学工具箱](/guide/math-toolkit)，然后从第一章按顺序往下。速成篇只讲读这本书会碰到的 Lean，而且是按 Rust 程序员的习惯来讲的。工具箱把后面反复出现的数学说法提前铺平。你要是等不及，也可以先往下读，遇到不认识的记号再回头查这两篇。

书里有四种提示盒。与其空讲，不如先让你看见它们长什么样：

::: info 数学小课堂
数学概念第一次出现时的补课。先给直觉，再给一个小例子。数学要是生疏了，先看这个盒子。
:::

::: tip Lean 深入
某项 Lean 4 的语法或特性第一次用到时，解释放在这里。一条定律被写成定理、给出证明时，也常常放在这里。
:::

::: tip Rust 视角
用你已经会的东西来对照，比如 `Option`、`Result`、trait、`Iterator::map`、`and_then`。你天天在写的那些，会在这里和范畴论对上号。
:::

::: warning 易错点
容易想岔，而且后文会反复绊到的地方。
:::
